# 安全与脱敏规范

本仓库是**公开**的，而它处理的东西天然带敏感标识。这份文档把"什么能进仓库、
什么不能、不能的东西放哪、怎么保证"钉死，避免再犯。

> **它存在的理由**：2026-09-18 / 09-19 连续两次泄漏 ——
> ① 一个改配置前顺手做的备份 `.env.bak-20260918-110124`（含真实 Admin Token）
> 没被 `.gitignore` 挡住；② 代理账密、4 个出口 IP、本机直连出口 IP 被写进
> README / 源码 / 工具注释并推到公开仓库。
> 两次都不是"不懂"，而是**没有任何自动检查**。

---

## 1. 标识分类：先判断，再决定放哪

写任何配置前，先按这张表分类。**判据是"贴进公开仓库会不会让别人获得你的能力，
或者把行为关联到你"**。

| 级别 | 是什么 | 例子 | 处置 |
|---|---|---|---|
| 🔴 **凭据** | 能直接换取权限的 | Admin Token、API Key、代理账密、JWT、私钥 | **只进 `.env`**；代码 `os.getenv(..., "")` **默认空**；曾泄漏的**必须轮换** |
| 🟠 **基础设施标识** | 能定位到你基础设施的 | Worker 子域、邮箱域名、出口 IP、本机绝对路径 | 不进仓库；本地值放 `.env`；文档用占位符 |
| 🟡 **风控标识** | 能把行为和某个身份关联起来的 | 邀请码 / 邀请人 ID、代理服务商与订阅名、出口 IP | 不进仓库；需要时走 env 且**默认空** |
| 🟢 **公开标识** | 贴出去也拿不到任何东西的 | `client_id`、服务端 RSA 公钥、目标站域名 | **可以**留默认值，但注释里必须写明"为什么它不是秘密" |

🔴 **出口 IP 同时是 🟠 和 🟡** —— 它既暴露你的基础设施，又能被目标站用来
把账号关联起来。这是本项目最容易被忽略的一类。

🔴 分类不是一次性判断：`client_id` 今天是 🟢，但如果哪天它开始携带会话信息，
就变成 🔴 了。**改了用途就重新分类。**

## 2. 代码规范

1. **单一配置入口。** 所有外部值经 `src/config.py` 读，不在业务代码里直接
   `os.getenv()`。这样"哪些值是外部的"只有一个地方要看。
2. **默认值只能空。** `os.getenv("IR_X", "")`。
   *例外*：🟢 类标识可以带默认值，但**必须**在注释里写明分类理由
   （见 `config.py` 里 `CLIENT_ID` 的写法）。
3. **缺项在入口报错，不要静默降级。** 由 `config.validate()` 统一检查。
   带着空值往下跑只会发一堆注定失败的请求，报错还指向错误的方向。
4. **日志 / 输出边界必须脱敏。** 凡是把配置值写进 stdout / 日志 / 报告的地方，
   先过 `redact.redact_url()`（抹掉 URL 里的 `user:pass@`）或
   `redact.redact()`（打成 `<N chars>`，**连前缀都不打**）。
   （模块在 `src/redact.py`；2026-09-19 从 `config.py` 拆出，因为它跟配置无关。）
   实测踩过：`tools/probes/probe_proxy.py` 原样打印 `IR_PROXY=<完整串>`，账密直接进终端。
5. **探针工具的 `--out` 默认脱敏**，需要原值要显式 `--no-redact`。
   报告经常被贴进 issue / 对话，凭据不该跟着走。
6. **删代码前先按值反查一遍。** `INVITER_USER_ID` / `INVITER_USERNAME` /
   `ACTIVITY_PATH` 三个常量就是典型：定义了、从未被引用 ——
   纯死代码，却把一个邀请码身份永久嵌在公开仓库里。
   ```bash
   git grep -n '<变量名>' -- .      # 按名字查
   git grep -n '<真实值>'  -- .     # 按值查（防动态引用）
   ```

## 3. 文档规范：占位符约定

文档里**只允许**出现下表的占位形式。用 RFC 保留段而不是编造 IP，
是为了让"这是示例"一眼可辨，也让闸门能精确放行。

| 类别 | ✅ 这么写 | ❌ 不要写 |
|---|---|---|
| 出口 / 主机 IP | `203.0.113.11`（RFC 5737 TEST-NET-3） | 真实 IP |
| 私有 / 本地 | `10.0.0.1`、`192.168.x.x`、`127.0.0.1` | — |
| Worker 子域 | `https://<worker-name>.<your-subdomain>.workers.dev` | 实例子域 |
| 邮箱域名 | `<your-mail-domain>` | 真实域名 |
| 代理串 | `203.0.113.30:764:USERNAME:PASSWORD` | 真实账密 |
| 本机绝对路径 | `<你的 mihomo 可执行文件>` | `F:/...` / `/home/...` |
| 代理服务商 / 订阅名 | `<订阅名>` | 服务商名 + 套餐号 |
| 凭据 | `<token>`、`<N chars>` | 值，**以及值的前几位** |

**保留段速查**（写文档直接挑一个）：
`192.0.2.0/24` · `198.51.100.0/24` · `203.0.113.0/24`

### 终端输出

`run.py` 的槽位预检表**会**打印出口 IP —— 那是它的用途（按出口看额度）。
正因如此：**这段输出不要粘进任何仓库、issue 或对话。**
代理 URL 在这张表里已经过 `redact_url()`，账密不会出现。

## 4. 目录规范

```
.env                    🔴 凭据唯一存放点（gitignored）
.env.example            ✅ 模板，入库，**不含任何真实值**
src/                    库代码
tools/                  运维脚本 / 探针 / 闸门
docs/                   规范与事故记录（公开可读，无值）
.workbuddy-ai/          🔒 本地私密数据（gitignored，全部不发布）
    state/                  运行态（配额台账）
    tmp/                    临时文件、批次日志（含邮箱/账号）
    exports/                探测报告、Key 导出
    proxypool/              mihomo 槽位配置 + slots.txt（**含节点账密**）
    memory/                 开发过程记录
```

**规则：**

* 新建文件前先问"它属于哪一层"。放错层 = 迟早泄漏。
  典型错误：把 `slots.txt` 放到仓库根（那里没有 `.gitignore` 家族规则兜底）。
* **`.gitignore` 按家族写，绝不枚举后缀。** 快照后缀不收敛
  （`.bak` / `.bak-<描述>` / `.old` / `.save` / `.tmp` / `~`），枚举永远补不完。
  ```gitignore
  .env
  .env.*
  !/.env.example      # 🔴 例外行不能省：上面那条会把模板一起吃掉，
                      #    而"误伤"是静默的（不入库、不报错）
  ```
  同型的第二个例外（2026-09-19 补）：`*.json` 会把测试用的**脱敏样本台账**
  一起吃掉，而它必须入库 —— CI 上唯一可用的台账来源：
  ```gitignore
  *.json
  !tests/fixtures/ledger_sample.json   # 只放行这一个文件，别写成 !tests/fixtures/*
  ```
* 🔴 **"例外行有没有生效"不能拿 `git check-ignore` 的退出码当判据。**
  实测：命中**取反规则**时它仍可能返回 `0`（并打出带 `!` 的那条规则），
  看起来像"仍被忽略"，但它其实已经放行了 —— 这个假信号会让人白改一通。
  权威判据是**未跟踪且未被忽略**的清单：
  ```bash
  git ls-files --others --exclude-standard | grep fixtures
  # 列出来了 = 例外生效；没列出来 = 仍被忽略
  git add -n <path>          # 交叉验证：说 add 就是会入库
  ```
  ⚠ 例外加错方向的代价不对称：**该入库的被挡住**是静默的（本地文件在、
  测试绿、CI 红）；**该挡的放行了**则还有内容层闸门兜底。
* **`.gitignore` 与闸门的文件名规则是两层，必须同时改。**
  只改一层会漂移成"一个放行一个拦截"，而真正决定出货与否的是 `.gitignore` 那层。

## 5. 闸门：怎么保证规范被执行

规范写在文档里没人看。所以有**三层**强制：

```bash
python tools/gates/install_hooks.py          # 一次性：挂 pre-commit + pre-push 钩子
python tools/gates/check_leaks.py            # 手动全量扫描
python tools/gates/check_leaks.py --history  # 连全部 git 历史逐 blob 扫
python tools/gates/selftest_check_leaks.py   # 验证闸门**真的会拦**（变异测试）
```

| 层 | 位置 | 拦什么 | 能被绕过吗 |
|---|---|---|---|
| 路径层 | `.gitignore` | 凭据文件、快照、日志、证书**不被跟踪** | 能（`git add -f`） |
| 内容层 | `tools/gates/check_leaks.py` | 已跟踪文件里的真实 IP / 凭据 / 令牌 / 实例子域 / 绝对路径 | 能（`--no-verify`） |
| 服务端 | `.github/workflows/secret-scan.yml` | 同上 + **全历史** | **不能** |

**闸门的设计约束**（每条都是踩出来的）：

* **fail-closed**：默认扫全部文本文件，只跳过真正的二进制。
  用"后缀白名单"决定扫什么 = fail-open，没人预料到的后缀会被静默跳过。
* **两层判据**：具体模式扫全部文本；高熵串**只**扫 `.json/.jsonl/.log/.txt/.csv`。
  扫 `.md` / `.py` 会把文档示例全报出来 —— **一吵就会被 `--no-verify` 绕过**。
* **项目自带模式**：自动读 `.env`，把**你真实在用的值**也当禁用串。
  这样"别把 .env 里的东西写回仓库"是自动生效的，不需要另外维护清单。
  （只提取真秘密：路径 / 数字 / 开关 / 公开标识会被排除，否则误报。）
* **自检必须做变异验证**：`selftest_check_leaks.py` 会造含假凭据的仓库，
  断言闸门**非 0 退出并点名文件**。"拿干净仓库跑一遍通过"只证明了它不过度拦截，
  **完全没有证明它会拦**。
* **自检文件自己不能用字面量写假凭据** —— 它也在扫描范围内，会自咬。
  用运行时拼接（`"203.0.114" + "." + "5"`），**不要**给它加扫描白名单
  （那等于开一个藏东西的口子）。

## 6. 事故处置流程

**先按通道逐个对账 —— 泄漏通道彼此独立，清理动作必须逐个通道重做一遍。**

| 通道 | 怎么查 | 本项目现状（2026-09-19） |
|---|---|---|
| git 对象 | `git log --all --full-history -- <path>` | 已用 `git-filter-repo` 重写，全历史逐 blob 扫 0 命中 |
| Release 资产 | `gh api repos/<o>/<r>/releases` | 空 ✅ |
| Tags | `gh api repos/<o>/<r>/tags` | 空 ✅ |
| GitHub Pages | `has_pages` 字段 | `false` ✅ |
| **fork** | `forks_count` | ⚠️ **2 个 —— 清不掉**，见下 |
| CI 缓存 / artifact | 平台后台 | 无 |
| 包仓库 | PyPI / npm | 未发布 |

### 🔴 重写历史 ≠ 凭据安全

**fork 共享对象库，旧 clone 里的副本删不掉。** 本项目有 2 个 fork，
重写前的旧提交在它们里面仍然可达。所以：

> **凡是进过公开仓库的凭据，一律当作已泄漏，必须轮换。**
> 历史重写只是止损（让新 clone 拿不到），不是恢复。

### 重写历史

见 `.workbuddy-ai/skills/git-history-secret-purge`。四条铁律：

1. 先建离线回滚锚点（`git bundle create --all`）**再**动历史；
2. 跑 `filter-repo` 前 `export CODEBUDDY_SAFE_DELETE_ENABLED=0`
   （否则批量删除被拦 → `.git/objects` 被清空 → 仓库当场损毁）；
3. 在 **bare 副本**上重写，主仓库工作区全程零改动；
4. 验证用 **tree sha** 而不是提交数 —— `--replace-text` 会把"脱敏提交"本身剪掉
   （替换后与父提交同内容），提交数变少是**对的**。
